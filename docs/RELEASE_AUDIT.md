# LLMLINK Cinema 4D — аудит 0.2.0

Дата: 22 октября 2026, America/Toronto. База: `c0f7c6c` (0.1.2). Проверен весь исходный код плагина, провайдеров, хранения данных, установщика и упаковки. Исправления предназначены для установленной macOS / Cinema 4D 2024.2.

## Оценка архитектуры

| Область | Вывод |
|---|---|
| Корректность | Основные найденные дефекты закрыты проверками. Очередь выполняется последовательно, неизвестные результаты не повторяются автоматически. |
| Стабильность | Восстановление после разрыва и ошибок записи усилено. Нативный процесс Cinema и сторонние плагины остаются общей точкой отказа. |
| Безопасность | Добавлены реальные проверки кода и входов. Полной изоляции произвольного Python/Cinema API нет; заявлять её было бы неверно. |
| Производительность | Убраны полные записи архива при наборе текста и копирование старых снимков сцены. Измерен выигрыш на существующем чате. |
| Сопровождаемость | Политика кода, атомарная запись и чтение процессов выделены в отдельные модули. Добавлены воспроизводимые регрессионные и нативные испытания. |

Удачные решения сохранены: отдельный процесс для модели; аутентифицированный локальный канал; изменения документа в основном потоке Cinema; проверка документа и ревизии перед изменением; резервная `.c4d`-копия; рендер отдельного клона; полный архив отдельно от контекста модели.

## Найдено и исправлено

| Приоритет | Дефект | Исправление и проверка |
|---|---|---|
| Высокий | Reconnect прекращался досрочно, если сломанный процесс ещё работал; интерфейс мог оставаться Busy | Ошибка закрывает соединение и снимает аутентификацию; Connect снова доступен. Перезапуск запрещён до окончания отмены старого рендера. |
| Высокий | Задание удалялось из очереди до записи активного задания | Сначала сохраняется полный активный элемент, затем новая очередь. Восстановление исключает активный ID, даже если старый снимок очереди ещё содержит его. |
| Высокий | Задание из очереди могло попасть в другой документ | Привязка к измеренному документу текущей работы. Несовпадение останавливает продолжение; новое задание в состоянии покоя может намеренно выбрать другую сцену. |
| Высокий | Python-защита была только текстом в промпте; `SystemExit` обходил обработчик | Проверка синтаксического дерева в двух процессах, запрет типовых системных/файловых/сетевых операций, рефлексии и управления жизненным циклом документов. `BaseException` обрабатывается на границе исполнения. |
| Высокий | Пустая карта MCP не доказывала отключение унаследованных интеграций Codex | Явное отключение каждого сервера через конечные ключи конфигурации; приложения и встроенные инструменты отключены. Реальный контрольный сервер не запустился. |
| Средний | Ошибка одного сообщения затирала следующее набранное | Существующий черновик сохраняется, отклонённый текст остаётся видимым. Повторное подключение не стирает текущий черновик. |
| Средний | Выбор модели и сообщение отправлялись отдельными командами | Настройки проверяются вместе с приёмом сообщения: ошибка не приводит к тихой отправке старому провайдеру. |
| Средний | Ошибки записи оставляли Busy либо незаметно меняли очередь/настройки | Атомарные приватные файлы с flush/fsync, откат неуспешного приёма/удаления/перестановки и сохранение прежних настроек. |
| Средний | Ввод текста переписывал весь архив каждую секунду | Черновик хранится в небольшом отдельном файле; тест проверяет неизменность основного архива. |
| Средний | Очереди и строки вывода процессов не имели границ | Ограниченные очереди, строки и stderr, освобождение читателей при отмене. |
| Средний | Раннее уведомление Codex о завершении могло потеряться до ответа на turn/start | Уведомления завершения сохраняются до обработки; проверено воспроизведением порядка сообщений. |
| Средний | Изменившаяся копия изображения проверялась не всеми провайдерами | Codex также проверяет хеш и размер перед передачей пути. Чтение ограничено 8 MiB + 1 байт. |
| Средний | Ошибка измерения сцены после рендера могла оставить зависшее состояние | Работник освобождается независимо от успешности повторного снимка; ошибка измерения указывается отдельно. |
| Средний | Частичная установка могла оставить копию плагина в сканируемой папке | Подготовка вне plugins, очистка после сбоя, отказ от символьного конечного пути, проверка Python 3.9+. |
| Низкий | Прокрутка истории могла забирать фокус у консоли/другого поля | Прокрутка выполняется только когда активна сама история. |
| Низкий | Короткий лимит excerpt мог вернуть весь исходный текст из-за среза `[-0:]` | Исправлены нулевой и малые лимиты, добавлен тест. |

Импорт 3D-файлов сохранён через `llmlink.import_asset(path)`: разрешён только путь из вложений текущего сообщения. Проверены и отказ без вложения, и успешный импорт собственной тестовой `.c4d`-сцены.

## Свежие доказательства

- Автоматический набор: 99 тестов прошли; подробности в `docs/VALIDATION.md`; включает прежние FIFO, Steer, Manual/Auto, 1000 запросов с имитацией модели, восстановление чатов, упаковку и новые ошибки границ. Это не 1000 реальных платных обращений к модели.
- Реальный Codex: корректный `done`, пустой код, около 4 секунд. Отдельно проверено отключение унаследованного MCP контрольным процессом.
- Реальный LM Studio: уже загруженная `qwen3.8-27b-uncensored-mlx`, корректный `done`, пустой код, 27.24 секунды. Модель не переключалась и не загружалась заново.
- Cinema 4D 2024.2: отклонение опасного кода и неверной ревизии, обработка SystemExit, ограничение Python-цикла за 8 секунд, куб/материал/камера/свет/ключи, контрольная копия, PNG 320×240, сохранение и повторное чтение `.c4d`, разрешённый/запрещённый импорт, стабильная ревизия после обновления импортированных данных.
- Установленная панель: восстановление связи при ещё живом старом процессе; сохранение выбранной модели, чата и черновика; 40 обновлений истории с сохранением фокуса ввода. Все пять проверок активации прошли, перезапуск Cinema не потребовался.
- Тесты выполнялись в отдельном документе. Исходная сцена возвращена и проверена по ревизии; дополнительно сохранена отдельная резервная копия.
- На реальном архиве из предыдущего обращения: подготовка контекста в среднем 0.16342 → 0.02026 секунды за 10 прогонов с tracemalloc, пик выделений 13,351,899 → 671,223 байта. В обоих случаях проекция 60,110 символов. Это ускорение подготовки контекста, не генерации модели и не рендера.

Первый нативный тест выявил ошибку завершения самого испытательного окна: уже поставленный в очередь Timer обращался к удалённому тестовому документу. Исправлен терминальный этап драйвера, проверка повторена. Импорт также потребовал дождаться штатного обновления анимации Cinema перед измерением стабильности. Финальный прогон этих проверок прошёл.

## Границы релиза

Эта сборка значительно укреплена, но отметка «ошибок больше никогда не будет» не обоснована.

1. Произвольный Cinema Python работает внутри процесса приложения. Синтаксические проверки не являются доказанным sandbox; сложный нативный вызов или сторонний плагин может зависнуть/аварийно завершить Cinema. Для более сильной гарантии требуется постепенно заменить произвольный код ограниченным набором типизированных операций.
2. Подтверждена конкретная macOS / C4D 2024.2. Windows, другие версии Cinema, Redshift, большие production-сцены и многочасовая нагрузка требуют отдельной матрицы испытаний.
3. Архив всё ещё целиком загружается в память; смысловая память модели может быть неточной. Следующий архитектурный шаг для очень больших архивов — индексируемый журнал и постраничная загрузка. Резервные копии и выходные файлы автоматически не удаляются.
4. Повреждение диска, исчезновение питания и разом несколько файлов состояния не защищены одной общей транзакцией. Активный маркер предотвращает автоматический повтор неизвестной операции, но не заменяет резервное копирование.
5. Публичное распространение требует собственного зарегистрированного Maxon Plugin ID и проверки установки/подписи. Текущий ID разработческий. Для локальной установки новый ID не подменялся вымышленным.

Справочный контракт Codex сверялся с [официальной документацией App Server](https://learn.chatgpt.com/docs/app-server) и схемой фактически установленного клиента. Важные предположения о порядке событий и конфигурации проверены отдельно, а не приняты только по документации.
